Descripción

Esta aplicación implementa lo visto en el recurso "Algoritmos de clave pública". Se usa AES-256 como algoritmo simétrico para cifrar los mensajes y RSA como algoritmo asimétrico para cifrar la clave de sesión y para hacer firmas digitales. Todo se hace en el navegador con la Web Crypto API de JavaScript, no se manda nada a ningún servidor.

Participantes: A (emisor), B (receptor), C (intruso) y T (amigo en común que certifica claves).

Paso 0. Generar las claves RSA

Aún no se generan las claves.

1. Confidencialidad (Figura 1 del recurso)

A le pide a B su clave pública. A genera una clave AES aleatoria (clave de sesión), cifra el mensaje con AES y luego cifra la clave de sesión con la clave pública de B usando RSA-OAEP. B usa su clave privada para sacar la clave de sesión y con ella descifra el mensaje.

2. Autenticación con firma digital (Figura 2 del recurso)

B saca el resumen r(m) del mensaje con SHA-256 y lo cifra con su clave privada, eso es la firma. A descifra la firma con la clave pública de B para obtener r(m), calcula su propio r'(m) y los compara. Si son iguales el mensaje es auténtico.

3. Ataque de intermediario (Figura 3 del recurso)

Cuando A pide la clave pública de B, C se mete en medio y le manda su propia clave. Así C puede leer los mensajes y hacerse pasar por B. Para evitarlo, la clave de B debe venir firmada por un amigo en común (T).

4. Comparación de rendimiento AES vs RSA

El recurso dice que los algoritmos asimétricos son mucho más lentos que los simétricos y que por eso en la práctica solo se usan para cifrar la clave de sesión. Aquí se cifran los mismos datos con AES, con RSA solo (por bloques) y con el esquema híbrido para comparar.
